## 2. 项目背景

5G专网业务涉及大量交付、开通、运维和项目资料，包括：

- 5G专网交付支撑方案。
- MEC部署与运维资料。
- 专网开通和纳管要求。
- 随行专网项目申请、网管反馈和资源配置。
- ToB物联网专网项目CPE、SIM卡、摄像头等设备配置。
- 通用运维规范、故障处理流程和案例。

目前资料以文档和结构化数据分散存在，缺少统一管理、统一检索和统一问答入口。业务人员需要同时查找文档知识、项目现场配置和网络资源，查询过程依赖人工经验。

本项目建设一套文档知识管理与智能检索平台，将文档、知识库、项目数据和辅助问答能力统一起来，解决资料查找难、数据来源不清晰、AI回答容易推测等问题。

## 3. 项目目标

### 3.1 一期目标

1. 建设统一的文档管理能力，支持文档分类、上传、预览、AI转Markdown、编辑、删除和概览统计。
2. 建设知识库能力，支持将Markdown导入知识库、向量化、语义检索和来源引用展示。
3. 建设项目数据查询能力，支持ToC随行专网和ToB物联网专网的只读查询。
4. 建设辅助问答能力，支持基于知识库和数据库结果回答问题，并严格约束空结果和来源标注。
5. 为后续二期完整智能体建设保留扩展能力。

### 3.2 二期边界

一期不作为完整智能体交付，以下能力列为二期方向：

- 自主任务规划和多步骤执行。
- Rerank精排和混合检索。
- 更丰富的运维工单联动。
- 主动告警、巡检和自动化处置。
- 更多数据源接入和智能体编排。

## 6. 使用场景

### 6.1 场景一：资料归档

业务管理员将5G专网项目资料上传到平台，按三级分类归档，并将Office或PDF文件转换为Markdown，供后续预览和知识库导入。

### 6.2 场景二：文档检索

运维人员通过文档管理列表按分类、名称和年份筛选，或通过知识库语义检索定位方案、手册和规范。

### 6.3 场景三：项目数据查询

运维人员查询随行专网项目DNN、ServiceID、UPF、地址池、路由和网络资源，或查询ToB项目CPE、SIM卡、固定IP、车辆/设备和摄像头配置。

### 6.4 场景四：辅助问答

用户向AI问答入口提问，系统先判断是否属于5G专网业务，再判断是现场项目问题还是知识问题，分别查询数据库或知识库后回答。

### 6.5 场景五：未命中处理

数据库或知识库未命中时，系统必须如实返回未找到提示，并引导用户补充关键查询条件，禁止模型推测。

## 8. 业务规则

### 8.1 查询范围规则

- ToC项目统计使用项目汇总视图。
- 资源、路由和文档表通过项目ID关联项目主表。
- 按项目名称查询地址池或路由时需关联项目表。
- CPE与SIM卡常规联查优先使用CPE/SIM联查视图。
- 文档片段不用于项目数量、资源数量等数值统计。

### 8.2 知识库回答规则

- 知识库引用中的附件名、文件名属于知识库内容。
- 只要正文片段已给出，必须按正文回答，不得声称未提供该附件内容。
- 知识库未命中时严格回复“知识库中暂未找到相关记录”。

### 8.3 AI问答规则

- 与业务无关问题直接提示不在受理范围。
- 无法判断业务方向时要求补充项目名称、项目编码、固定IP、ICCID、MSISDN、车辆/设备编号、DNN、ServiceID、UPF等。
- 数据库未命中时严格回复“未找到相关记录”。
- 数据库查询失败或未命中时，不得把知识库内容伪装成数据库查询结果。

## 10. 验收标准

### 10.1 文档管理验收

1. 能维护三级分类。
2. 能上传文件并记录版本、分类、年份、备注和上传时间。
3. 能预览PDF、Office、图片、文本、CSV和Markdown。
4. 能提交AI转MD，并展示排队、处理中、成功和失败状态。
5. 转换成功后能查看Markdown和图片。
6. 能编辑文档元数据并删除文档。
7. 概览页能按状态、文件类型和分类统计数量及源文件大小。

### 10.2 知识库验收

1. 能将Markdown导入知识库。
2. 能完成向量化。
3. 能基于知识库内容回答部署、运维、配置等问题。
4. 回答能展示知识库引用。
5. 命中内容中的图片能正常访问。

### 10.3 数据查询验收

1. 能查询ToC随行专网项目、网络资源、地址池路由和文档片段。
2. 能查询ToB项目、CPE/SIM和摄像头配置。
3. 查询只能访问允许表，不能执行写操作。
4. 分页正常，单页不超过200条。
5. 项目统计口径正确，不使用文档片段作为资源数量。

### 10.4 辅助问答验收

1. 非5G专网问题提示不在受理范围。
2. ToB现场问题先查数据库，ToC现场问题先查数据库。
3. 数据库命中时展示数据库来源标注。
4. 数据库未命中时严格返回“未找到相关记录”。
5. 知识库未命中时严格返回“知识库中暂未找到相关记录”。
6. 不支持编造项目名、IP、ICCID、MSISDN、DNN等数据。
7. 支持基于历史上下文补充查询条件后继续回答。

## 12. 风险与建议

### 12.1 一期风险

- 知识库未启用重排，复杂文档的检索精度仍可提升。
- ToB数据目前项目数量较少，后续需要持续补充。
- 手工编辑的ToC项目数据在重新导入原始资料时可能被覆盖，需要建立数据维护规范。
- 大文档图片资源清单较长，依赖大文本字段和资源代理能力。

### 12.2 建议

- 二期引入混合检索和Rerank精排。
- 建立原始资料变更、导入、知识库重建的规范化流程。
- 将更多ToB项目资料形成标准化文档后导入知识库。
- 完善AI回答的可解释性、审计日志和人工反馈闭环。
