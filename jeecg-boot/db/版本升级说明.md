# 版本升级方法

> JeecgBoot属于平台级产品，每次升级改动较大，目前做不到平滑升级。

### 增量升级方案

#### 1.代码合并
 本地通过svn或git做好主干，在分支上做业务开发，jeecg每次版本发布，可以手工覆盖主干的代码，对比合并代码；

#### 2.数据库升级
- 从3.6.2+版本增加flyway自动升级数据库机制，支持 mysql5.7、mysql8; 
- 其他库请手工执行SQL, 目录： `jeecg-module-system\jeecg-system-start\src\main\resources\flyway\sql\mysql`
> 注意： 升级sql只提供mysql版本；如果有权限升级, 还需要手工角色授权，退出重新登录才好使。

#### 3.其他数据库脚本说明
  原先官方默认提供oracle和SqlServer的脚本，但是维护成本太高，未提供脚本的数据库，可以参考下面的文档自己转
   https://my.oschina.net/jeecg/blog/4905722
   （注意：定时任务的表qrtz_*，需要删掉用原始的脚本重新执行一下）
   quartz-2.2.3-distribution.tar.gz放到百度网盘中，大家自己下载，执行所需数据库脚本
   https://pan.baidu.com/s/1WrmZdUuAPg3iBwJ-LoHWyg?pwd=8mdz 

#### 4.兼容问题
 每次发版，会针对不兼容地方重点说明。

### 2026-08-18 ai 分支数据库处理记录（合并 main 后）

#### 背景
合并 `main` 时，main 的 `application-dev.yml` 带入了 `spring.flyway.enabled: true`，而 ai 分支原本为关闭状态；同时引入了 JimuChatBI 相关依赖与 flyway 脚本。

#### 处理内容
1. **JimuChatBI 建表脚本改为幂等版本**
   - 文件：`flyway/sql/mysql/V3.9.2_2__add_jimuchatbi.sql`
   - `DROP TABLE` 改为 `CREATE TABLE IF NOT EXISTS`，不再删表；
   - `INSERT INTO` 改为 `INSERT IGNORE INTO`，已存在数据不覆盖、不因主键/唯一键重复报错；
   - 移除重复字典的 `DELETE`（避免清掉自定义敏感词）；
   - 补充 `chat2bi_table_meta` 建表（“AI数据表”功能依赖）；
   - 结尾恢复 `SET FOREIGN_KEY_CHECKS = 1`。
2. **关闭 dev 环境 flyway 自动升级**
   - `application-dev.yml`：`spring.flyway.enabled` 改回 `false`（ai 分支原配置）。
3. **`jeecgai` 库手动执行 jimuchatbi 脚本**（已验证，可重复执行）
   - 8 张 `chat2bi_*` 表、敏感词字典（`c2b_sens_abuse`/`c2b_sens_politics`）、`积木 ChatBI` 菜单、演示数据已落地；
   - `flyway_schema_history` 手动补录 `3.9.2.2 add jimuchatbi`，`checksum` 为 NULL（flyway 校验跳过）。
4. **ai5g 插件脚本移出共享 flyway 目录**
   - ai5g 脚本是 ai 分支私有补丁（main 分支不存在），原与 jimuchatbi 同版本号 `3.9.2.2`；
   - 为避免占用 main 的版本号线、防止 main 后续发布同版本导致 flyway 冲突，已移至：
     `db/ai5g/ai5g_domain_query_plugin.sql`（不在 flyway 扫描目录内）；
   - 删除 `flyway_schema_history` 中对应记录；`jeecgai` 库中 AI5G 对象（`biz_ai5g_*` 表、`airag_mcp` 插件）已存在，不受影响。

#### 注意事项
- dev 环境 flyway 处于关闭状态，后续新迁移需**手动执行**对应 SQL，并建议同步补录 `flyway_schema_history`（`checksum` 置 NULL）。
- 全新库部署时 AI5G 功能需手动执行 `db/ai5g/ai5g_domain_query_plugin.sql`（脚本幂等，可重复执行）。
- 若将来重新开启 flyway：本地脚本与库记录一致（最新 `3.9.2.2`），ai5g 不在 flyway 目录，不会与 main 未来版本号冲突。
