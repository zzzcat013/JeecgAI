# 机房运维模块说明

## 1. 模块定位

机房运维模块承载三类业务：

- `inspection`：机房巡检
- `fault`：故障处理
- `engineering`：工程施工

当前实现由四部分组成：

| 部分 | 位置 |
| --- | --- |
| JeecgBoot 后端 | `jeecg-boot/jeecg-module-biz/.../roomops` |
| Vue3 前端 | `jeecgboot-vue3/src/views/biz/roomops` |
| 钉钉小程序 | `/Users/zhangxj/MiniProjects/validateDingtalk` |
| VPS 前置服务 | `https://inspection-api.700906.xyz` |

小程序负责现场采集和离线补传，VPS 负责接收上传数据并暂存，JeecgAI 负责主动拉取、落库、文件转存 MinIO 和任务闭环。

## 2. 开发边界

- 后端业务代码只能放在 `org.jeecg.modules.biz.roomops` 包内。
- 前端业务代码只能放在 `src/views/biz/roomops` 目录内。
- 所有业务表必须使用 `biz_roomops_` 前缀。
- 基础维度：专业 `core_network / CORE / 核心网`，地市 `TY / 太原`。
- 默认测试机房：`TY01ROOM1500 / 一枢纽15楼机房`。

## 4. 核心流程

### 4.1 任务分派闭环

1. 有权限用户在 JeecgAI“任务分派”创建任务。
2. 指定执行人时任务状态为 `ASSIGNED`；不指定时为 `AVAILABLE`。
3. 任务创建/编辑后自动推送 VPS：`POST /api/tasks/push`。
4. 小程序首页展示“我的任务”和“待接任务”。
5. 执行人打开任务后，任务 ID 自动带入业务表单，提交时以任务 ID 作为记录 ID。
6. 小程序提交后 VPS 有新数据，JeecgAI 主动拉取并调用 `markSubmitted` 将任务置为 `SUBMITTED`。
7. 派单人在任务列表确认完成或驳回重发。
8. 删除/批量删除任务时同步软删除 VPS 侧任务，小程序不再展示。
9. 归档/恢复任务同步 `archived` 状态到 VPS，小程序不再展示已归档任务。

### 4.2 工程管理流程

1. 在“工程录入”填写基本信息、开工报告并上传附件。
2. 在“工程列表”维护状态、查看附件、下发工程任务。
3. 工程任务完成提交后，工程状态不会自动变化，由管理员在“工程列表”手动更新。
4. 验收完成后可归档工程。

### 4.3 VPS 数据同步流程

```text
小程序上传 -> VPS 暂存 -> JeecgAI 定时拉取 /api/sync/pending
                       -> 落库 biz_roomops_record / biz_roomops_photo
                       -> 照片下载并转存 MinIO
                       -> 回写任务状态 SUBMITTED
                       -> 调用 /api/sync/ack 确认
```

任务状态回拉（接单、提交、驳回等 VPS 侧变更）由 `RoomopsSyncPullJob` 定时任务每 5 分钟执行一次：

```text
GET /api/tasks/changed -> upsert biz_roomops_task -> 导入任务流转记录
```

注意：`sys_quartz_job` 中该任务 `status=0` 表示“运行中/正常调度”，并非停用。

同步批次号格式：

```text
ROOMOPS-PULL-YYYYMMDDHHMMSS
```

### 4.4 小程序离线补传

现场无网络时可先“保存到本地待上传”，缓存照片本地路径和记录字段；有网后重新进入小程序，在首页补传。补传记录使用 `uploadMode = offline_retry`，直接上传使用 `uploadMode = online`。

### 4.5 任务删除与归档同步

删除链路：

1. JeecgAI 删除任务：先写 `biz_roomops_task_tombstone` 墓碑，再调 VPS `POST /api/tasks/delete`。
2. VPS 侧软删除（`deleted_at` 置位），`/api/tasks/my`、`/api/tasks/available`、`/api/tasks/changed` 均不再返回。
3. 若删除通知 VPS 失败，定时回拉发现墓碑会跳过该任务并自动补偿删除，避免任务被回拉重建。

归档链路：

1. JeecgAI 归档/恢复时把 `archived`、`archivedAt`、`archivedBy` 随 `POST /api/tasks/push` 推送。
2. VPS 侧 `roomops_tasks.archived` 置 1/0，任务列表与回拉接口过滤 `archived=1`。
3. 重新下发同一 `taskId` 会清除 `deleted_at`，使软删任务复活。

### 5.1 业务记录编号


## 10. 与小程序配合

### 10.1 任务下发

JeecgAI 调用 VPS：

```text
POST /api/tasks/push
Header: X-Roomops-Pull-Token
Body: { "tasks": [ ... ] }
```

任务字段包括 `taskId`、`businessType`、`taskTitle`、`taskContent`、`roomId`、`assigneeUserid`、`assigneeName`、`status`、`archived`、`archivedAt`、`archivedBy` 等。

### 10.2 小程序任务接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/tasks/my` | 我的任务 |
| `GET /api/tasks/available` | 待接任务 |
| `POST /api/tasks/claim` | 接单 |
| `GET /api/tasks/changed?limit=200` | JeecgAI 回拉任务变更 |

说明：`/api/tasks/my`、`/api/tasks/available`、`/api/tasks/changed` 均不返回已归档（`archived=1`）或已软删（`deleted_at` 非空）的任务。

### 10.3 小程序上传接口

| `POST /api/inspection/upload` | 巡检 |
| `POST /api/fault/upload` | 故障 |
| `POST /api/engineering/upload` | 工程施工 |

### 10.4 身份获取

小程序进入页面后按以下顺序获取姓名：

1. `dd.getOpenUserInfo`
2. `dd.getAuthCode`
3. 将免登码 POST 到 `/api/dingtalk/userinfo`
4. 后台通过钉钉开放平台换取用户信息

JeecgAI 侧通过“同步用户数据”菜单从 VPS 同步钉钉通讯录，用户数据进入 `biz_roomops_dingtalk_user`。

### 10.5 照片与附件

- 小程序默认上传原图，可切换为压缩图。
- 每张照片可记录拍照时的经纬度、精度、拍摄时间、备注。
- VPS 同步时照片下载到 JeecgAI 并转存 MinIO，路径为 `records/{recordId}/{storedFilename}`。

## 13. 注意点与经验教训

### 13.1 模块与表

- 只改 `roomops` 模块，避免影响 JeecgAI 其他功能。
- 所有表带 `biz_roomops_` 前缀。
- 业务差异字段单列，方便 SQL 查询，不要把巡检/故障/工程差异全部塞进 JSON。
- 专业和地市预留扩展：当前只启用 `core_network / TY`，数据结构已支持多个专业和地市。

### 13.2 附件与文件

- 工程附件做了 MD5 去重：同一工程、同一附件分类下相同文件不会重复入库，唯一索引 `uk_biz_roomops_eng_att_duplicate` 兜底。
- 删除附件会同时删除 MinIO 对象。
- Office 在线预览依赖容器内的 `soffice`；Dockerfile 已安装 LibreOffice，删除或缩小镜像会影响 docx 预览。
- 上传大小限制：dev/docker 为单文件 100MB，prod 当前为 10MB，按环境调整 `spring.servlet.multipart.max-file-size`。
- 前端是 PWA，发布后需要强刷页面，避免 Service Worker 缓存旧版本。

### 13.3 同步与任务

- VPS 与 JeecgAI 之间使用固定 token，配置必须与环境一致，避免“好几处配置不一致”。
- 任务创建、编辑、确认、驳回都会尝试自动下发 VPS；失败时可使用“下发全部”或单条“下发”手动重试。
- 任务回拉通过 `RoomopsSyncPullJob` 定时任务完成，Quartz 使用 6 段 Cron，配置时不能同时写“月中的某天”和“星期几”。
- `X-Roomops-Notify-Token` 只用于通知，不传业务数据和照片。
- 同步日志保留批次号和错误信息，排查拉取失败先看 `biz_roomops_sync_log`。

### 13.4 小程序

- iOS 不支持钉钉 `readNFC`，NFC 入口默认隐藏。
- 离线待上传依赖小程序本地缓存和临时照片路径，长时间后可能失效，建议尽快补传。
- 人员姓名优先从钉钉身份获取，失败时可手动填写；正式人员建议在“同步用户数据”中先同步通讯录。
- 默认上传原图；使用压缩图片时调用钉钉压缩能力，可降低传输量但会损失细节。
- 小程序提交时如果带了任务 ID/工单号，则以该 ID 作为记录 ID，不再自动生成。

### 13.5 其他

- 时间统一按 `Asia/Shanghai` 处理，避免上传时间与本地时间不一致。
- 前端列表使用小尺寸表格和缩略展示，操作按钮按状态控制，避免“已提交任务还能下发”这类逻辑错误。
- 生产环境角色授权建议通过 JeecgAI“角色授权”界面维护，SQL 只作为初始化和迁移手段。
